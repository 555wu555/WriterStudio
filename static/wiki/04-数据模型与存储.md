# 04 · 数据模型与存储

## 数据模型（[models/](../../models/Project.h)）

全部为纯聚合 struct，不继承 QObject、无行为（个别 inline 辅助函数除外），可在任意层拷贝传递。

### 作品与章节 — [Project.h](../../models/Project.h)

```cpp
struct Chapter {
    QString id;        // UUID，身份标识（文件名、排序、备份都以它为键）
    QString title;     // 展示名，可随意改，不影响磁盘路径
    QString filePath;  // 相对作品目录的路径（chapters/<id>.md）
    qint64  wordCount; // 作品库统计用
};

struct Project {
    QString id, name, genre;   // 主标签
    QStringList tags;          // 多标签
    QString synopsis, authorName; // 作品自己的笔名（可与默认作者不同）
    QDateTime createdAt, updatedAt;
    QList<Chapter> chapters;   // 顺序即章节顺序（拖拽排序改这里）
    QString lastChapterId;     // 上次写到哪章（恢复现场）
};
```

设计原则：**ID 是身份，名称是展示**——改标题不触发文件改名，重排只改数组顺序。

### 人物与世界 — [Entity.h](../../models/Entity.h) / [Relationship.h](../../models/Relationship.h) / [WorldData.h](../../models/WorldData.h)

```cpp
struct Entity {
    QString id, kind;   // kind: 人物/地点/组织/物件 统一模型
    QString name, role; // role 仅人物有意义的"角色定位"
    QString summary;    // 简介
    QString background; // 人物背景（非人物留空）
    QString notes;      // 详细设定
};

struct Relationship {
    QString id, fromId, toId;
    QString label;        // fromId → toId 的称呼
    QString reverseLabel; // toId → fromId 的称呼，空 = 未定义
    QString notes;
};

struct WorldData { QVector<Entity> entities; QVector<Relationship> relationships; };
```

一条关系就是一条有向边 + 两个称呼，图谱页按"当前选中节点视角"展示称呼。删除实体会联动清理关联关系（EntityStore 侧处理）。

### 作品设定 — [StorySetup.h](../../models/StorySetup.h)

```cpp
struct WritingConvention {          // 写作约定五件套
    QString viewpoint, tense, style, rhythm, constraints;
    bool isEmpty() const;
};

struct storySetup {
    QString coreIdea;   // 核心设想
    QString outline;    // 自由文本整体大纲
    QString viewpoint, tense, style, rhythm, constraints; // 作品级约定
    WritingConvention writingConvention() const;
};

// 关键规则：作品约定任意一项有值 → 整组用作品；全空 → 整组用全局。AI 提示词与界面共用此函数。
inline WritingConvention effectiveWritingConvention(const storySetup &, const WritingConvention &global);
```

## 磁盘布局

路径常量与拼接全部集中在 [StoragePaths.h](../../storage/StoragePaths.h)（单一事实来源），入口 [main.cpp](../../main.cpp)：

```
<数据根>                          # 新用户默认使用 AppLocalDataLocation；已有旧作品库继续沿用
├── projects/                     # StoragePaths::ProjectsDirName
│   └── <作品UUID>/
│       ├── project.json          # Project 元数据 + 章节清单
│       ├── setup.json            # storySetup（核心设想/大纲/约定）
│       ├── entities.json         # WorldData（实体 + 关系）
│       └── chapters/
│           ├── <章节UUID>.md     # 章节正文（Markdown 纯文本）
│           ├── backup/
│           │   └── <章节UUID>.md.bak   # 上一版自动备份
│           └── bak/              # 早期版本的备份目录（兼容读取）
└── archive/                      # 归档作品（与 projects 同级）
```

本机设置（与数据根无关，跟随用户账户）：

- **QSettings INI**：`QSettings::IniFormat + UserScope`，组织/应用名均为 `WriterStudio`（[AppSettings.h](../../storage/AppSettings.h)）。保存作者资料、数据根路径、Ollama/云端模型配置、系统提示词、各类开关。
- **Windows 凭据管理器**：各云端配置的 API Key（唯一不落 INI 的敏感数据）。

`project.json` 内章节只存**相对路径**（`chapters/<id>.md`），因此整库迁移/改名作品目录不影响引用。

## 存储层 API（[storage/](../../storage/ProjectStore.h)）

统一签名风格：`static bool op(..., QString &error)`，错误通过出参返回中文可读信息；先验证到临时对象、成功后才提交正式状态。

## 持久化策略要点

1. **自动保存**：输入停止约 2 秒触发（`Writer::autoSaveTimer_`），另有 Ctrl+S 与切章/退出确认；保存失败绝不会被误标为"已保存"。
2. **上一版备份**：每次保存先把旧文件轮换到 `.bak`，写作页提供"查看上一版"只读预览与恢复。
3. **归档即移动**：删除作品 = 移入 `archive/`，可恢复；归档前处理目标冲突与"作品仍在写作标签中"的边界。
4. **导入两段式**：解析为临时结果 → 预览对话框确认 → 才创建真实文件；用户取消不写盘。
5. **目录迁移可验证**：整库复制后逐项核对才切换数据根。
