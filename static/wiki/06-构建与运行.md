# 06 · 构建与运行

## 环境要求

| 组件 | 版本/说明 |
| --- | --- |
| 操作系统 | Windows（凭据存储、Schannel TLS、部署脚本均按 Windows 设计） |
| Qt | 6.5.3 MinGW 64-bit；配置 CMake 时传入本机 `CMAKE_PREFIX_PATH`，无需修改源码 |
| 编译器 | MinGW-w64（GCC，支持 C++20）或 MSVC（部署段有 MSVC Debug `d` 后缀处理） |
| CMake | ≥ 4.1 |
| Qt 模块 | Core、Gui、Widgets、Network |
| 链接系统库 | `Advapi32`（Windows 凭据管理器 API） |

## 构建步骤

```powershell
# 1. 在项目根目录配置；将 Qt 路径替换成本机实际位置
cmake -S . -B cmake-build-debug -DCMAKE_BUILD_TYPE=Debug -DCMAKE_PREFIX_PATH="<Qt 安装目录>/6.5.3/mingw_64" -G "MinGW Makefiles"

# 2. 编译
cmake --build cmake-build-debug

# 3. 运行
.\cmake-build-debug\write.exe
```

构建启用 `AUTOMOC/AUTORCC/AUTOUIC`，源文件在 `add_executable()` 中**逐个显式列出**——新增 `.h/.cpp`（尤其含 Q_OBJECT 的）必须同步加入 CMakeLists.txt。

### 构建后自动部署（Windows）

[CMakeLists.txt](../../CMakeLists.txt#L118-L171) 的 POST_BUILD 钩子会把以下内容拷到可执行文件目录，因此构建产物**开箱即用**：

- 平台插件 `plugins/platforms/qwindows.dll`
- 图像插件 `plugins/imageformats/qjpeg.dll`
- **TLS 插件 `plugins/tls/qschannelbackend.dll`**（HTTPS 必需；使用系统 Schannel，无需部署 OpenSSL DLL）
- `Qt6Core/Gui/Widgets/Network.dll`（Debug 下自动带 `d` 后缀）

> 若运行时报"无法使用 HTTPS：缺少 Qt TLS 后端"，即说明 qschannelbackend 插件未随程序部署——这是 [CloudGenerationService::start](../../WorkPlaces/Generation/CloudGenerationService.cpp#L31-L36) 的显式检测给出的提示。

## 运行期配置

### 数据目录

- 首次运行读取 QSettings 的 `library/dataRoot`；未配置时让用户选择作品库位置，并提供当前 Windows 用户的 `AppLocalDataLocation` 作为默认选项。
- 数据根下必须存在 `projects/`（main.cpp 启动时会 mkpath；切换数据根要求目标已含 projects/）。
- 启动会检查作品目录是否可写；失败时弹窗可选择其他目录。若要使用已有作品，应选择包含 `projects/` 的原作品库目录。
- 可在设置页发起整库迁移（DataRootStore + DataRootMigration：校验 → 复制 → 验证）。
- 本仓库内 `WriterStudio/` 目录即默认数据根的样例数据（几个测试作品），非代码。

### 本机设置文件

QSettings INI（`IniFormat + UserScope`，组织/程序名 `WriterStudio`），位于 `%APPDATA%\WriterStudio\WriterStudio.ini`。存储：作者资料、数据根、Ollama 配置、云端配置列表（不含 API Key）、系统提示词、各开关。**API Key 单独存 Windows 凭据管理器**（控制面板 → 凭据管理器 → Windows 凭据，目标名含配置 ID）。

### AI 模型配置

**方案 A · 本地 Ollama**

1. 安装并启动 [Ollama](https://ollama.com)（默认监听 `http://127.0.0.1:11434`）。
2. 拉取模型，例如 `ollama pull deepseek-r1:8b`（默认配置即此模型）。
3. 应用内：设置 → 模型与提示 → 本地服务 · Ollama → "获取已安装模型" → 选择模型 → 测试 → 保存 → 设为写作模型。
4. 模型名带 `:cloud` / `-cloud` 后缀（如 `qwen3:235b-cloud`）时走 Ollama Cloud 分支（更长超时、纯文本输出、更大生成预算）。

**方案 B · OpenAI 兼容云端**

1. 设置 → 模型与提示 → 云端服务 → 选服务商模板（DeepSeek / 阿里云百炼 / OpenAI / 自定义）→ 新建。
2. 填基础地址（程序自动追加 `/chat/completions`，**地址栏不要带该路径**）：

   | 服务 | 基础地址示例 |
   | --- | --- |
   | DeepSeek | `https://api.deepseek.com` |
   | 阿里云百炼 | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
   | OpenAI | `https://api.openai.com/v1` |

3. 填 API Key → "测试此配置"（会真实计费一次短请求）→ 保存 → "使用选中的云端配置"。
4. DeepSeek 会自动附加 `thinking:{type:disabled}`；其他服务不受影响。

**验证 AI 链路**：写作页正文末尾停止输入约 1 秒，光标后出现灰色短语 → Tab 采纳。失败时看底部状态标签（悬停见原因），或设置页"查看请求记录"核对最终 JSON。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 构建报找不到 Qt | 配置 CMake 时传入正确的 `-DCMAKE_PREFIX_PATH`；更换工具链时用**新的构建目录**（旧缓存会记旧路径） |
| HTTPS 云端请求直接失败 | qschannelbackend.dll 未部署；重新 CMake 构建让 POST_BUILD 拷贝 |
| 建议一直显示"模型回复不符合短语格式" | 模型输出了整句/多逗号/换行；看"查看请求记录"里的原始回复，必要时调模型或在系统提示词中强化约束 |
| 本地模型总是空回复 | 推理模型把预算花在思考上；程序会自动加倍预算重试一次，仍空则换小模型或关闭思考（gpt-oss 已自动 low） |
| DeepSeek 建议为空且报生成长度上限 | 确认 baseUrl 是 `api.deepseek.com`（thinking disabled 参数靠 host 判断） |
| 作品列表为空但目录有数据 | 检查设置页显示的作品库位置；新用户默认使用系统应用数据目录，旧目录有作品或归档时继续沿用；换机器后需选择包含 `projects/` 的原作品库目录 |
| 新增源文件未参与编译 | 源码需逐个列入 CMakeLists.txt 的 `add_executable()` |
